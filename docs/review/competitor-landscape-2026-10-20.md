## 三、功能边界（评审建议，采纳为规划口径）

- **控制平面 Server**：Inventory · 身份权限 · 任务编排 · 审计 · 告警 · 资源关系 · 证书与配置
- **执行平面 Agent Core**：通信 · 身份 · 心跳 · Capability · 任务生命周期 · 资源限制 · 安全更新
- **Provider Adapter 独立概念**：AWS/阿里云/腾讯云/PVE 的开停机不走被管机内部 Agent，
  由 Server 或专用 Provider Worker 直接调云 API —— 避免 Agent 做成巨型程序，
  也为未来 Go/Rust 双实现留路。（**与多云 Provider 评审直接呼应，归并入同一工作流**）

三类不照搬：①企业 IT 管理套件全套（补丁/软件分发/合规做到基础维护即可）；
②不重造 VPN 与视频编解码（Tailscale/RustDesk 的价值是接入与管理不是自研每层协议）；
③上层业务治理（玩家/匹配/运营逻辑永不入仓，延续既有边界）。

## 四、建议深读的四套源码

1. **Zabbix Agent 2**（Agent 内核）：插件 API、Collector 调度、超时、并发限额、缓冲。
2. **Teleport**（安全与连接）：Agent 身份、访问证书、连接代理、资源权限、审计模型。
3. **Portainer Edge Agent**（分布式节点控制）：反向连接、隧道生命周期、任务下发、远程更新。
4. **Tactical RMM**（运维体验）：Shell/脚本/计划任务/资产/服务操作如何协作。

结论：Cockpit 已覆盖多数竞品基础功能；下一步补的是 **Agent 可靠性、安全边界、跨平台一致性、
资源管理体系**，不是横向堆功能。先把 Agent Core 做小、Capability 契约做稳、Provider 适配层独立，
将来换 Rust Agent 也不必推翻架构。
