# 持久化任务恢复与重试设计（项 31）

> 依据：决策项 31（保留重启后遗留任务标失败的保守行为；并入 23，先落任务身份/去重/人工重试审计，再对证明可重复的动作开放自动恢复）。
> 状态：**设计稿**。实现并入项 23 主线；不自动重放所有 failed/pending 命令、不承诺任意脚本恰好执行一次（决策明确不做）。
> 边界：不另开与 23 重复的重试引擎（决策明确不做）。

## 1. 任务类型分类（已核实）

现有 job 仅 `exec` 与 `cancel`（`internal/agent/rpc/job_provider.go:35-36`）；`exec` 经 `sh -c` 执行任意命令（`job_provider_unix.go:17`），有超时/长度/输出上限（`jobExecMaxTimeout=300s`、`jobExecMaxCommand=16KB`、`jobExecMaxOutput=64KB`，`job_provider.go:45-50`）。

| 类别 | 例 | 可自动重试 | 说明 |
|---|---|---|---|
| **只读查询** | `vms.list`、`containers.list`、系统探测 | ✅ 安全 | 幂等、无副作用 |
| **幂等状态设置** | status 置位（如已 stopped 再 stop） | ✅ 安全（幂等） | 重复执行结果一致 |
| **任意脚本** | `job.exec`（`sh -c`） | ❌ 默认不自动 | 命令已执行但回复丢失时，重放可能重复创建/扣费/删除（决策项 31「风险最大的是重复副作用」） |

## 2. 任务身份/去重/租约设计

- **任务 ID**：server 下发 `job.exec` 必带（`ExecParams.ID` 已存在，`job_provider.go:58`）；作为去重键。
- **目标去重**：同任务 ID 重复下发→拒绝或幂等（只读/幂等类）；任意脚本重复→拒绝并告警。
- **租约/心跳**：执行中任务持租约，心跳续期；过期→视为失败/悬挂，按类别处理。
- **过期窗口**：任务过期（超租约+宽限）→标失败（保守），不自动重放。

## 3. 恢复规则（派发前/后与结果丢失）

- **派发前失败**：任务未到 agent→可安全重派（只读/幂等类）；任意脚本需人工确认。
- **派发后结果丢失**：命令已执行但回复丢失→不能仅凭任务状态判断是否重放（决策项 31「不能仅凭任务状态判断」）；只读/幂等类可重放，任意脚本默认不自动重放，标「需人工确认」。
- **重启后遗留**：保留「重启后遗留任务标失败」的保守行为（决策项 31 明确），不自动重放。
- **人工重试审计**：人工确认重试记录审计事件（operator、task ID、reason、result），不自动。

## 4. 故障注入验收（待实现后）

- 对只读/幂等/任意脚本三类分别故障注入：模拟回复丢失、租约过期、重启遗留——验证各自恢复规则。
- 验收需可注入故障的运行环境（agent 桩），属实现后的测试项，本次设计稿不跑。

## 5. 决策对照

本设计落实项 31 的「对只读查询、幂等状态设置、任意脚本分类（§1）」「明确任务 ID、目标去重、租约/心跳和过期窗口（§2）」「设计派发前后及结果丢失时的恢复规则（§3）」；故障注入验收（§4）待实现后。保留重启遗留标失败的保守行为，不自动重放所有 failed/pending、不另开重复重试引擎。
