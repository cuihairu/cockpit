# Agent 准入与 secret 生命周期设计（项 29）

> 依据：决策项 29（在已有默认拒绝和 enrollment 基础上补轮换/吊销设计，并入 23/24；旧部署迁移必须先有保留入口）。
> 状态：**设计稿**。实现并入项 23/24 主线；本次不操作实际 secret。
> 边界：不重新开放默认注册、不批量一刀切吊销、不另起与 23/24 重复的身份系统（决策明确不做）。

## 1. 现状盘点（已核实）

- **准入**：`config/config.go:166-176` `AgentRegistrationConfig`（`enrollment_secret`、`allow_unknown`，默认 fail-closed）；`server/websocket.go:24-31` 注册时经 `hashAgentSecretForRegistration=storage.HashAgentSecret` 哈希落库、`agentRegistrationPolicy` 读准入策略。
- **secret 生命周期**：仅「注册签发＋哈希存储」；未见轮换/吊销逻辑（grep 无 revocation/rotate）。
- **结论**：默认拒绝已落地；轮换/吊销未实现，属待立项设计。

## 2. 生命周期模型（签发→使用→轮换→吊销→审计）

| 阶段 | 设计 | 说明 |
|---|---|---|
| 签发 | `enrollment_secret` 限时 enrollment（一次一节点或限时窗口） | 已有准入，补「限时」语义 |
| 使用 | 每节点独立 secret，哈希存储（既有） | 保持现状 |
| 轮换 | 分批轮换（不整批）；新旧并存过渡窗 | 轮换中不中断合法节点（决策项 29 理由） |
| 吊销 | 吊销后连接处理：立即拒绝该 secret；已有连接按策略断开/限时 | 凭据泄露或设备退出时停止其访问 |
| 审计 | 签发/轮换/吊销事件记录（无凭据） | 不另起身份系统 |

## 3. 迁移路径（旧部署保留入口）

- **先保留入口**：旧凭据停用前，先确认该 agent 已具备新凭据且可达；否则保留旧入口（决策项 29「旧部署迁移必须先有保留入口」）。
- **分批**：按 agent 分组逐步轮换，每批完成验证后再停用旧凭据；任一批失败则回退（保留旧凭据），不整批推进。
- **可恢复性**：选一个可本地恢复的节点先验（决策项 29 立即执行动作）——需节点/设备，本次待用户。

## 4. 与 23/24 的关系

- 准入/secret 生命周期**并入项 23（Capability 契约）/24（资源级权限）**主线（决策项 29），不另起重复身份系统。
- 能力契约（`agent-capability-contract.md`）提供能力门控；本设计提供 secret 生命周期；二者在同一主线按依赖排序。

## 5. 待用户项

- **管理员预置需求**：明确预置节点范围/方式（决策项 29「管理员预置需求」）。
- **迁移路径试点**：选一个可本地恢复的节点先验轮换/吊销。
- **吊销策略**：吊销后已有连接是立即断还是限时——用户拍板。

## 6. 决策对照

本设计落实项 29 的「盘点现有节点和凭据关系（§1）、设计限时 enrollment、分批轮换和吊销后的连接处理（§2-3）」；试点验证与管理员预置需求待用户。不重新开放默认注册、不批量一刀切吊销。
