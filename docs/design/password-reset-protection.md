# 密码重置与验证码限速设计（项 30）

> 依据：决策项 30（若相关入口对公网开放或邮件可用，优先做这一小项；与登录限流区分，独立完成忘记密码/重置/验证码的防滥用设计）。
> 状态：**设计稿**。入口核对已完成（§1，无需凭据）；限速实现与验证待用户确认入口是否对公网开放/邮件可用后单独立项。
> 边界：不把「登录已限流」当全部入口已保护、不默认加 CAPTCHA、当前单实例不为此先上共享数据库（决策明确不做）。

## 1. 入口暴露与现有保护盘点（已核实，无需凭据）

- **入口**：`server/server.go:354-356` 注册 `/api/auth/forgot-password`、`/api/auth/reset-password`、`/api/auth/verify-reset-code`，均在 `authService().Middleware` 之外（无 JWT——找回语义本身不需登录）。
- **令牌/验证码**：`auth/password_reset.go` 内存 map 存储，30 分钟过期，6 位验证码，`ValidateResetCode:108` 直接字符串比对，**无失败次数限制、无冷却、无统一响应**。
- **邮件链**：`config.EmailConfig/SMTPConfig`（`config.go:186-194`）、`SetEmailConfig` 全局，`net/smtp` 直发。
- **现有保护**：登录限流已有 `loginAttemptLimiter`（`server/login_limiter.go`，进程内、IP+用户名桶），**仅覆盖登录**；forgot/reset/verify 三入口无独立限速。
- **暴露面**：默认 `cfg.Server.Host="127.0.0.1"`（`config.go:379`）——默认不对外。**是否对公网开放/邮件可用**取决于部署配置，待用户确认（触发条件）。

## 2. 限速设计（IP 与账号/邮箱双维度）

| 维度 | 建议 | 说明 |
|---|---|---|
| IP | 有限窗口（如每 IP 每小时 N 次） | 复用 `loginAttemptLimiter` 桶模式，进程内 |
| 账号/邮箱 | 发送冷却（同邮箱两次发送间隔 ≥ M 分钟） | 防邮件轰炸/额度损耗 |
| 统一响应 | 不管入口/账号是否存在，返回同一响应 | 不泄露账号存在性（决策项 30「验不泄露账号存在性」） |
| 失败计数 | 验证码失败计数，超限作废令牌 | 防暴力猜码（6 位码空间小） |
| 冷却 | 超限后冷却期，冷却内统一拒绝 | 规则过严会阻碍正常找回——按「有限窗口」而非永久封禁（决策「过严或按账号直接封禁又可能阻止正常用户找回」） |

- **单实例**：进程内限速即可，不为单实例先上共享数据库（决策边界）；未来多实例再评估共享计数。
- **不默认加 CAPTCHA**（决策边界）。

## 3. 验证条件（待触发后）

- 正常找回流程（邮件链真实可达）、限流生效、不泄露账号存在性——需运行中 server＋邮件链；本次设计稿不验证（决策项 30「验正常找回、限流及不泄露账号存在性」）。
- **触发条件**：入口对公网开放，或邮件发送可用（决策项 30「若相关入口对公网开放或邮件发送可用，建议优先做这一小项」）——当前默认 `127.0.0.1`，触发未明，待用户确认。

## 4. 决策对照

本设计落实项 30 的「先核对 forgot/reset/verify-code 各入口暴露情况、邮件发送链和现有保护（§1）」「为 IP、账号/邮箱设计有限窗口、发送冷却和统一响应（§2）」；验证（§3）待触发条件确认后推进。与登录限流区分、独立设计，未默认上 CAPTCHA/共享数据库。
