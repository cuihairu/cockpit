# P1 资源池：资源归属与单写入负责人设计

> 依据：`docs/review/2026-10-30-decisions.md` 项 21（先确定「一个资源同一时刻只有一个写入负责人」，P0 闭环后只挑小资源池试点）。
> 状态：**设计稿**。实现待 P0 闭环＋用户确认试点期望容量与预算后单独立项。
> 前置：`docs/design/cloud-provider.md` §6 已立单写入规则——「写操作只能经 Cockpit `ComputeProvider` 发出；若引入 OpenTofu，写入所有权须先裁决」（P1 决策点，已记录，无机制）。

## 1. 问题与约束

- **争抢核心风险**：OpenTofu 与 Cockpit 都写同一资源，可能互相撤销对方动作，产生停机或费用循环（决策项 21 理由）。
- **约束**：不让两个控制器直接改同一资源；不一次铺开云网络全家桶、不做 CRD 全量模型（决策明确不做）。
- **边界**：本设计只定所有权与交接规则，不实现 Reconciler 逻辑（P1 实现项）。

## 2. 资源归属矩阵

| 资源类别 | 写入负责人 | Cockpit 对它的权限 | 说明 |
|---|---|---|---|
| **OpenTofu 管理的资源** | OpenTofu | 只读观察；或提交计划（plan，不 apply） | Cockpit 不直接执行变更；只读契约核对走 `ListInstances` |
| **Cockpit 独占管理的试验资源** | Cockpit | 允许 Reconciler 写 | 仅此类别允许自动协调；试点只挑这一类 |
| **外部归属资源** | 外部系统 | 默认只读 | 不识别归属者时 fail-closed 为只读 |

## 3. 所有权交接（adjudication）

- **登记表**：每资源记 `owned_by ∈ {opentofu, cockpit, external}`，落 `cloud_instances` 或独立归属表（待 P0 表结构确认后定）。
- **交接流程**：变更 `owned_by` 前，先确认对方无进行中操作（Operation 状态非 terminal 则拒绝）；交接需审计事件（operator、from、to、reason）。
- **冲突拒绝**：同一资源的写操作并发时，后到者拒绝（409/失败），不排队覆写——单写入负责人保证不会出现两写者。

## 4. 暂停开关与审计条件

- **全局暂停开关**：Reconciler 提供 `paused` 标志；暂停时所有自动写停止，人工写仍可（审计）。
- **审计事件**（每写）：`cloud.reconcile.{create,start,stop,delete}` 记录 operator、resource、action、operation ID、owned_by——无凭据。
- **回退**：任一自动写失败 → 记录 error 原文，不自动重试超过 N 次（避免费用循环）；重试需人工确认。

## 5. 待 P0 闭环后确认项（用户拍板）

- **试点资源池**：只挑一小类 Cockpit 独占试验资源；期望容量与预算由用户确认（决策项 21「待 P0 完成后再确认试点的期望容量及预算」）。
- **预算策略**：预算限制先作用于新建/告警/审批，不默认关闭生产（决策明确不做「预算告警自动关生产」）。
- **P0 前置**：P0 未完成不排 P1 实现（决策边界）。

## 6. 决策对照

本设计落实决策项 21 的「在方案中列资源归属」「列出所有权交接、暂停开关、冲突拒绝和审计条件」，并保留「待 P0 完成后再确认试点」的拍板门。不实现 Reconciler/预算引擎（P1 实现项，待拍板）。
