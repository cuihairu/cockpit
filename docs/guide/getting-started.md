# Quick Start


## Requirements

- Go 1.27 or a compatible version
- Node.js and pnpm, for building the web UI
- The Server listens on `127.0.0.1:9000` by default

## Build

At the repo root:

```bash
go build -o cockpit ./cmd/cockpit
go build -o cockpit-agent ./cmd/cockpit-agent
```

If you need the web UI:

```bash
cd web
pnpm install
pnpm build
cd ..
```

The config generated by `cockpit init` defaults to `server.static_dir: ./web/dist`. Only when both `server.static_dir` and the `STATIC_DIR` environment variable are **unset** does the Server root path return the API hint; when a directory is configured but does not exist (e.g. the web build was never run), the root path returns 404.

## Initialize

```bash
./cockpit init -example
```

This creates the following in the current directory (the `data/` directory is created too; `cockpit.db` is created automatically the first time the database is opened):

```text
config/
  cockpit.yaml
data/
inventory/
  example.yaml
```

Key parts of the default config:

```yaml
server:
  host: 127.0.0.1
  port: 9000
  static_dir: ./web/dist

database:
  path: ./data/cockpit.db

inventory:
  path: ./inventory/example.yaml
  watch: false
  strict: false
```

`inventory.watch: true` makes the Server watch and hot-reload a single inventory file. `inventory.strict: true` treats a missing inventory path, a parse failure, or a failed initial sync at startup as a Server startup error; with the default `false` those only get logged and the Server still starts.

## Sync the inventory

```bash
./cockpit sync -config config/cockpit.yaml
```

You can also specify the inventory and database explicitly:

```bash
./cockpit sync -inventory inventory/example.yaml -db data/cockpit.db
```

After the sync finishes, check the database state:

```bash
./cockpit status -db data/cockpit.db
```

## Start the Server

An admin password must be provided when the Server starts:

```bash
export ADMIN_PASSWORD='change-this-password'
./cockpit server -config config/cockpit.yaml
```

Windows PowerShell:

```powershell
$env:ADMIN_PASSWORD = 'change-this-password'
.\cockpit.exe server -config config/cockpit.yaml
```

Once running, visit:

- Web UI: `http://127.0.0.1:9000`
- Health: `http://127.0.0.1:9000/health`

The default admin username is `admin` and can be changed via `ADMIN_USERNAME`.

## Start an Agent

First configure `server.agent_registration.enrollment_secret` on the Server. New Agent
registration is rejected by default, so installers, service registration, and manual starts
must provide the same `-secret`; after enrollment it becomes that Agent's authentication key.
For Docker deployments, use `AGENT_ENROLLMENT_SECRET` in `.env`.

### One-line install (recommended)

One command per platform (anonymous direct download from the nightly release, with automatic OS and CPU architecture detection; after installing it automatically runs `cockpit-agent --version` to verify; re-running upgrades):

Linux / macOS:

```bash
curl -fsSL https://raw.githubusercontent.com/cuihairu/cockpit/main/install.sh | bash
```

Windows graphical install (recommended, an Inno Setup installer): download
`cockpit-agent-setup-nightly.exe` (a `.sha256` checksum file of the same name is provided alongside) from the
[nightly release](https://github.com/cuihairu/cockpit/releases/latest) and double-click
to run it: installs to `%ProgramFiles%\Cockpit Agent`, adds Start Menu + desktop shortcuts (with the agent
icon), the install wizard asks for the Server WebSocket address and Agent enrollment secret, offers to "register as a Windows service and
start at boot" (auto-restart on crash at 5s/10s/20s), and adds a standard Add/Remove Programs entry. Silent
install:

```powershell
# Silent install (also pass /SECRET in the default secure mode; it must match the Server enrollment_secret)
.\cockpit-agent-setup-nightly.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SERVER=wss://cockpit.cuihairu.site/ws /SECRET=%AGENT_ENROLLMENT_SECRET%
```

For headless Windows / fleet provisioning use the PowerShell script (PowerShell 5.1+ / pwsh):

```powershell
irm https://raw.githubusercontent.com/cuihairu/cockpit/main/install.ps1 | iex
```

Optionally register a boot-time service (systemd / launchd / Windows service), passing the connection info
together with `--with-service`:

```bash
curl -fsSL https://raw.githubusercontent.com/cuihairu/cockpit/main/install.sh | \
  bash -s -- --with-service --server wss://cockpit.cuihairu.site/ws --secret "$AGENT_ENROLLMENT_SECRET"
```

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/cuihairu/cockpit/main/install.ps1))) `
  -WithService -ServerUrl "wss://cockpit.cuihairu.site/ws" -Secret $env:AGENT_ENROLLMENT_SECRET
```

Supported matrix: Linux amd64 / arm64 / armv7, macOS amd64 / arm64, Windows
amd64 / arm64 (all built nightly); when the architecture is unrecognised the script reports a clear error.
For manual deployment, service parameters and troubleshooting see [deployments/README.md](https://github.com/cuihairu/cockpit/blob/main/deployments/README.md).

### Manual start

OpenWrt routers need no manual compilation: the nightly release provides multi-architecture
`.ipk` packages (install with opkg, supervised by procd, configured via UCI); the install steps are in
OpenWrt Agent packaging design.

Other cases: download the `cockpit-agent` binary for your platform (or compile it locally).
The Server must configure `server.agent_registration.enrollment_secret`; use the same value
for the first registration, then keep using it as that Agent's authentication secret. Inject
it securely through an environment variable and run on the managed node:

```bash
./cockpit-agent start -server wss://cockpit.cuihairu.site/ws -secret "$AGENT_ENROLLMENT_SECRET" -region home -zone datacenter
```

The main binary also offers a compatible entry point with the same parameters as `cockpit-agent start`:

```bash
./cockpit agent -server wss://cockpit.cuihairu.site/ws -region home -zone datacenter
```

Common parameters:

```bash
./cockpit-agent start \
  -server wss://cockpit.cuihairu.site/ws \
  -id server01 \
  -secret YOUR_AGENT_SECRET \
  -region home \
  -zone datacenter \
  -labels env=home,role=hypervisor
```

Key points:

- `-server` must point at the Server's agent WebSocket entry, usually ending in `/ws`.
- `-secret` is required in the default secure mode. The first-registration value must match the Server's enrollment secret; after registration, reconnects continue using this Agent secret. New Agents are rejected by default if the Server has no enrollment secret configured.
- Without `-region` / `-zone`, the Agent tries to read `COCKPIT_REGION` / `COCKPIT_ZONE`, otherwise uses `unknown`.

### Windows service management

`cockpit-agent` ships its own service subcommands (requires an administrator PowerShell). Both install paths
(the installer and the script) share this single entry point, service name `CockpitAgent` (start at boot + auto-restart on crash at 5s/10s/20s):

```powershell
# register (if already registered this upgrades: refresh the start parameters then restart)
.\cockpit-agent.exe service install -server wss://cockpit.cuihairu.site/ws

.\cockpit-agent.exe service status    # running state and start type
.\cockpit-agent.exe service stop
.\cockpit-agent.exe service start
.\cockpit-agent.exe service uninstall  # stop and deregister (run automatically when uninstalling the installer)
```

The service has no console; logs are written to `%ProgramData%\CockpitAgent\agent.log` (the connection info lives
in `config.env` in the same directory).

## Minimum production configuration

A production deployment should set at least:

```bash
export ADMIN_PASSWORD='use-a-strong-password'
export TOTP_ENCRYPTION_KEY="$(openssl rand -base64 32)"
# the vault master key (falls back to TOTP_ENCRYPTION_KEY when unset, see §2 V5 in docs/guide/vault-design.md)
export COCKPIT_VAULT_KEY="$(openssl rand -base64 32)"
export ALLOWED_ORIGINS="https://cockpit.cuihairu.site"
export PRODUCTION=true
```

And change the Server config to listen externally:

```yaml
server:
  host: 0.0.0.0
  port: 9000
```

Terminating TLS through a reverse proxy is recommended, with Agents connecting via `wss://.../ws`.

Default config path precedence:

1. the path given by `-config`
2. `./config/cockpit.yaml`
3. `./cockpit.yaml`
4. `/etc/cockpit/config.yaml`

The full key list — notification channels (Herald / ntfy / webhook / Telegram), DNS and ACME credentials (Cloudflare / DNSPod / Aliyun), overlay cloud tokens (ZeroTier / Tailscale) and so on — is documented in the comments inside the repo's [`config/cockpit.yaml`](https://github.com/cuihairu/cockpit/blob/main/config/cockpit.yaml); secret-type config should be injected via environment variables (`CLOUDFLARE_API_TOKEN`, `DNSPOD_LOGIN_TOKEN`, `ALIYUN_ACCESS_KEY`, `ZEROTIER_API_TOKEN`, `TAILSCALE_API_TOKEN`, etc.).

## End-to-end smoke test

The repo ships a minimal closed-loop verification script (starts a server + agent in a temp directory, syncs the inventory, asserts the resource API is non-empty):

```bash
./scripts/e2e-smoke.sh          # Linux/macOS
pwsh ./scripts/e2e-smoke.ps1    # Windows
```

Exit code 0 means the whole chain is healthy; on a non-zero exit the tail of `server.log` is printed automatically. Keep the logs for debugging: `E2E_KEEP_LOGS=1` / `-KeepLogs`.

## Don't want to compile? Use Docker

The official image is pushed by CI to `ghcr.io/cuihairu/cockpit` (multiple tags: `latest` / `main` /
short sha; a `v*` tag additionally produces a semantic-version series) — all the deploy host needs is Docker:

```bash
cp deployments/docker/.env.example deployments/docker/.env
vi deployments/docker/.env   # ADMIN_PASSWORD / JWT_SECRET are mandatory
docker compose -f deployments/docker/docker-compose.yml up -d
```

Full deployment guide (tag strategy, guacd remote access, reverse proxy, backup/rollback, troubleshooting):
[Docker deployment](/operations/deploy-docker).
