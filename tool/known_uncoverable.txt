# Go 覆盖率豁免台账（known_uncoverable）
#
# 口径（对齐 web/tool/known_uncoverable.txt 与 mobile 同名文件）：未覆盖
# 语句块必须在本表登记并附理由，由 tool/coverage_check.sh 校验（未登记即红）。
#
# 登记项格式：<仓库相对路径>:<起行>,<止行> <理由>
#   - 止 > 起 时按「区间」解释：块起始行落在区间内即视为已登记（用于成片
#     豁免，如探针 main() 场景编排）
#   - 起 = 止 时按「单行」解释：块起始行等于该行
#
# 四类登记理由：
#
#   1. 场景编排 main() —— 验收探针主流程。真机验收（起 server/agent/容器/
#      浏览器/远控会话）才有意义，进程内单测只能造出「假真机」；真机证据落
#      .acceptance/ 各目录 probe.log。与 internal/agent/rpc/service_launchd_
#      stub.go、service_windows_stub.go 同属结构性边界（guac/probe 收口先例，
#      见 todo 2026-10-01 覆盖率规则 b）。
#   2. 真机命令默认闭包 —— 注入点（*Cmd/osExit）的默认实现本身要真跑
#      systemctl/docker/sudo/systemd-run，单测恒注入桩覆盖分支，默认闭包体
#      在测试进程内不可达。
#   3. 死防御 —— 契约上不可达（如 strings.Split 非空串恒 ≥1 段），保留防御
#      代码不删（同 guac/probe StdinPipe 先例）。
#   4. 平台专属执行层 —— 仅在非 Linux 构建标签下存在，Linux 跑不到其测试。
#
# 行号漂移即门禁红（须同步本表），这是刻意的：漂移常意味着代码真变了，复核
# 豁免是否仍成立。区间登记的漂移只提醒不失败（区间覆盖语义）——但区间外的
# 新增缺口仍会红，故区间止行应随文件末尾收紧。
